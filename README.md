# Optimizing Speculative Decoding on an RTX 5070

A technical write-up of how I made SGLang's NEXTN speculative decoding for Qwen3.5-2B up to 2.1× faster on an 8 GB laptop GPU (RTX 5070 Laptop, SM120), without changing the BF16 target model.

The article is a single static page: `index.html` plus `style.css` and SVG figures. It loads no JavaScript and makes no external requests.

## Preview locally

From this folder:

```bash
python -m http.server 8000
```

Then open <http://localhost:8000>. Opening `index.html` directly from disk also works.

## Rebuild the page

The article source is `article.md`. The figures are generated from the files in `data/`.

```bash
pip install markdown-it-py pygments   # build-time only
python make_charts.py                 # data/ -> assets/*.svg
python build_site.py                  # article.md -> index.html
```

## Regenerate the evidence (optional)

`data/` was produced from my experiment repository by two scripts. They re-read existing traces, run summaries, the experiment ledger and one Nsight Compute report. They do not benchmark or profile anything. They need the raw run directories, which are not part of this folder.

```bash
NCU=/path/to/ncu python tools/extract_evidence.py /path/to/sglang-decode-critical-path .
python tools/vocab_coverage.py /path/to/sglang-decode-critical-path > data/runs/vocab_coverage.txt
```

## What is in this folder

| Path | Contents |
|---|---|
| `index.html`, `style.css` | The article (generated) and its stylesheet |
| `article.md` | Article source |
| `assets/` | SVG figures, generated by `make_charts.py` |
| `data/ledger.jsonl` | Every experiment I ran, including failures. `[L53]` in the article means line 53. |
| `data/runs/` | Paired A/B comparisons (`compare.py` output), correctness report, power and clock telemetry, vocabulary coverage |
| `data/profiler/` | Critical-path analyses of CUPTI traces, one median round per timeline, kernel launch configurations, Nsight Compute metrics (CSV), isolated head benchmarks |
| `code/patches/` | My changes to an installed SGLang 0.5.21 package, as diffs |
| `code/scripts`, `code/tests`, `code/profiling`, `code/configs`, `code/data` | Benchmark harness, correctness test, profilers and variant definitions (local paths replaced by placeholders) |
| `tools/` | The scripts that produced `data/` |

Raw traces (tens of MB each) and the 70 MB Nsight Compute report are not included.

## Publishing to GitHub

Nothing here has been committed or pushed. To publish it as its own repository with GitHub Pages:

1. Create an empty public repository on GitHub, without a generated README.
2. From this folder:

   ```bash
   git init
   git add .
   git status
   git commit -m "Publish speculative decoding write-up"
   git branch -M main
   git remote add origin <your-repository-url>
   git push -u origin main
   ```

3. In the repository, open **Settings → Pages**. Choose **Deploy from a branch**, branch `main`, folder `/ (root)`.

The empty `.nojekyll` file turns off Jekyll, so files under `data/` and `code/` are served exactly as committed.

Before pushing, check `git status`: it should list only the files in the table above.
